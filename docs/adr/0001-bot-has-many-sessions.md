# 一个 Bot 多条会话

Bot 曾被定义成唯一一条持续会话。产品要分开跟踪一项项对话任务，因此 Bot 改为全体助手共用的 `web` profile 上的启动身份；其下每条会话一对一对应一条 Harness Session，由桌面注册表认领。dsh 继续保存事件日志。

## 考虑过的做法

- 维持一 Bot 一会话。执行状态不会被新会话掩盖，但多项任务无法并存。
- 一个任务拆成多条 Harness Session，或许多任务共用一条 Session。任务边界会和官方日志错位，所以改成严格一对一。
- 按 Bot 拆进程或 profile。这和 DSH 原则冲突。能力放在 Bot 的 preset 上，每条会话启动时使用它。

## 后果

同一工作区路径同时只执行一条会话。归档、删除和待核对都落在认领上，不删除 dsh 日志。Bot 视图和会话视图是同一份认领的两个入口。一级 Tasks、Outcomes 不是这个对象。
