# MyAid 产品蓝图（原则版）

描述产品目标与业务规则的**原则层**；装配与协议细节见 [ARCHITECTURE.md](ARCHITECTURE.md)，DSH 集成原则见 [DSH_PRINCIPLES.md](DSH_PRINCIPLES.md)。对外产品概述见根 [README.md](../README.md)。用词见根 [GLOSSARY.md](../GLOSSARY.md)。产品收窄的决定见 [ADR 0006](adr/0006-lorca-style-bot-app.md)，本轮验收见 [specs/2026-11-13-bot-app](specs/2026-11-13-bot-app.md)。

## 产品定位

MyAid 是一个**类 lorca 的桌面 Bot 应用**：管理一组 Bot，同时和多个 Bot 长线对话，并配置它们跑在什么模型上。

- **能力底座**：官方 DeepSeek Harness（`dsh`）——Session 执行、工具、插件、审批与事件真源。
- **多端壳**：Native Shell（NSH）——桌面与未来移动端共用的产品 UI / 原生框架。
- **产品对象**：**Bot**（联系人式助手档案；能力 = 派生 **Agent preset**）与它的**一条长对话**；对话由按时间相连的**段**（Session）组成，段可以落在不同的 dsh Workspace。
- **界面**：左侧扁平的 Bot 列表（Pin + 按最近活动排序 + 新建），中间分屏区（**Pane**）同时看几个 Bot；Bot 详情从 Pane 顶部打开为弹窗；⌘, / ⚙ 打开整页设置。整套界面中英双语。
- **生活与工作域不在骨架里**：Mail / Task / Knowledge / Note / Spaces 的界面与定位已移除；这些能力以后可由插件或 Bot 接入。

### 运行与数据拓扑（目标）

- **一个桌面端为本**：App 的执行与权威运行落在一台桌面机上的 Host + 官方 `dsh web`（web profile）；桌面 UI 是主控制面，不是「每台设备各自一套执行面」。
- **数据与操作在本地**：注册表、工作区与执行都在该机（数据根约定 `~/.myaid`）；不以云端同步目录为产品真源。模型凭据仍走上游 dsh settings，不进客户端文件。
- **多端可链接**：手机等其它端经 Relay 等通道**连回**这台桌面本机；其它端不打包独立 `dsh web`，Bot / 凭据只在桌面管理。
- **关 UI ≠ 关本机**：用户明确启用产品后台后，Host（及目标中的 Relay）可作为 OS Background Service 常驻，使本机在无桌面窗体时仍可被多端链接、继续已接纳工作；遇审批时可能等待用户在任一已连接端答复。

机制细则见下节「本机常驻与升级」；配对与链路可靠性另案设计。产品口语 **Runner** = 本机 `dsh web` / web profile 执行面（非 DSH 专名）。

## 本机常驻与升级

服务于上一节拓扑：让「桌面为本、本地操作、多端可连」在关窗后仍成立。

- 首次打开只查询本机 Background Service 状态；用户明确「启动后台」才申请登记 / 启动。
- 系统禁用后台后不自动改用其他常驻方式；保留数据与修复入口，恢复批准后仍须明确启动。
- 升级默认等待无活动执行、待处理输入与待审批；「立即升级」须确认。保留 Session / 队列 / 核对记录；不补发输入、不自动答复审批。

## Bot · 长对话 · 段（原则）

决定见 [ADR 0006](adr/0006-lorca-style-bot-app.md)；对象与 dsh 的映射见 [BOT_SESSION_MAP](BOT_SESSION_MAP.md)。

- **Bot**：联系人式档案；能力真源为共用 `web` profile 上的一个 Agent preset（模板绑定或派生；`plugins` 承载指令、工具、skills、可选 MCP 等）。≠ live Agent。**一个 Bot 只有一条长对话。**
- **长对话**：一个 Bot 的全部历史，由按时间相连的**段**组成。段之间在界面上有分隔线（日期 + 工作目录）；更早的段向上滚动加载。
- **段（Session）**：长对话里的一段 = 一条 dsh Session（事件日志真源）。段可以落在**不同的 dsh Workspace**；换工作目录就开新段，旧段保留自己的目录。只有最新段可发送；旧段可复制、不可续聊。接近上下文上限时在同一段内 **Compact**，不自动新开段。
- **新话题**：命令面板的「新话题」或 `/new` 开新段，之前的内容仍在上方。
- **认领**：Session 必须被某个 Bot 认领才进入产品列表；认领就是长对话里的一段，注册表存它的 `sessionId`、`workspaceId` 与称呼，段可跨 Workspace。
- **归档**：归档 **Bot**（注册表标记）：它退出左侧列表，搜索可找回并取消归档；段与日志保留。段的单独归档 / 删除不在本轮。
- 执行结束 ≠ 有未决审批；缺少审批 UI 不能默认放行。
- 域对象不是 Session；禁止把任何域列表塞进 Session 事件模型冒充产品存储。

## 配置所有权

| 真源                | 内容                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------- |
| dsh / 上游 settings | 模型供应商、端点、凭据（密钥不入客户端文件）                                                 |
| 桌面注册表          | Bot（identity、模板引用、默认模型、默认工作目录、归档位）与它的段（认领 / Workspace / 标题） |
| dsh / Workspace     | Workspace 的 path、title、Session 顺序、置顶与归档集合；段只引用它                           |
| 界面偏好            | 主题、语言、窗口、Pane 布局、Pin 的 Bot 顺序                                                 |

桌面独占写注册表；移动端（未来）只读快照。

## 输入与状态

- 发送前保存稳定请求标识与正文；超时 ≠ 未接纳。
- 区分草稿、发送待确认、已接纳、执行中、执行结束；按 **段（Session）** 计算。
- 停止当前执行、撤回未领取输入、停止后台为三项独立操作。
- 首版对话可先交付纯文本；附件、记忆与插件化域的深度集成为后续阶段。

## 能力与扩展

- 执行与工具优先复用官方 `dsh` / 已装插件；产品缺口才建 `myaid-plugin-*`（见 [DSH_PRINCIPLES.md](DSH_PRINCIPLES.md) §4）。
- 初始化把模板当时映射的 Agent preset id 绑定到该 Bot。单独配置能力 → 派生 preset id（覆盖 `plugins`）；模板引用保持不变。
- 该 preset 是这个 Bot 下各段的启动身份。保存后，正在执行的一轮不打断；空闲后同一 Session id 可用新 preset 恢复（受 DSH「首 turn 后锁定」等规则约束时，按上游行为新开 Session）。
- 需授权的工具调用必须可审批；缺少审批 UI 不能默认放行。
- 多端 UI 与原生能力走 NSH；不另起平行前端框架树。

## 多端（目标）

- NSH 覆盖桌面与移动**控制面**；执行与权威数据仍在那一台桌面本机。
- 手机目标形态**单栏**：Bot 列表 → 长对话，Bot 详情为全屏页；不另起 `dsh web`。
- 经 Relay 转发密文帧；其它端链接本机。Bot / 凭据只在桌面管理。配对与可靠性另案设计。

## 验收（原则）

- 仅支持经本机验证的官方 `dsh` 版本；不兼容时阻止发送并保留草稿。
- Host 控制协议与客户端原生适配须联调；`SMAppService` 以签名成品为准。
